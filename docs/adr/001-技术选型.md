# ADR 001：桌面框架技术选型（Electron vs Tauri vs Pure Java）

**背景**：启动器需要：下载大文件、解压、运行外部 Java 进程、系统钥匙串、跨 Apple Silicon/Intel、对新手友好的现代中文界面。

**对比**（数据来源：各官方仓库公开基准与社区常见实测，Tauri 体积/内存数据为 WebView 复用系统组件的典型值；Electron 数据为本项目实测）：

| 维度 | Electron（本选型） | Tauri | Pure Java (JavaFX/Swing) |
|---|---|---|---|
| 安装包体积 | ~170MB（实测） | ~8-15MB | ~60-150MB（需捆绑 JRE 或要求用户装 Java） |
| 空闲内存 | ~120-180MB（实测） | ~60-120MB | ~150-300MB |
| 启动速度 | 1-2 秒（实测） | <1 秒 | 2-5 秒 |
| 跨平台一致性 | 高（自带 Chromium） | 中（依赖系统 WebView 版本差异） | 中（LAF 各平台差异大） |
| 新手兼容 | 最好：无需 Java；JavaFX 反而要求用户装 Java | 好 | 差（启动器要求先装 Java 是悖论） |
| 生态 | 前端生态最全 | Rust 后端，生态成长中 | Maven 生态 |
| 维护成本 | 中（包体大、需更新 Chromium） | 中（需 Rust 技能） | 高（UI 开发效率低） |

**决策**：选择 Electron。关键理由：①启动器的目标用户没有 Java，Pure Java 方案自相矛盾；②本项目主进程已是纯 Node 模块，核心逻辑与 UI 天然分离（见 U.2），未来若需迁移 Tauri，核心（下载/启动/实例）可以 Rust 重写或以 CLI 保留，前端直接复用；③大文件下载、进程管理、钥匙串在 Node/Electron 中均有成熟 API。

**备选与迁移路径**：若未来包体积成为硬性要求，将 `main/core` 移植为 Tauri 的 Rust 命令层，`renderer/` 原样复用（已做到 UI 与核心仅通过 IPC 契约耦合，见 docs/ipc.md）。
